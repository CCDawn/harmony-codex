# 语音创建故障：HTTP 503 与等待期限

更新时间：2026-10-13 23:42（北京时间）。最新实测已接通，但启动仍慢。

## 证据

1. 独立、无麦克风的桌面原生请求跟踪：请求阶段约29.728秒后收到HTTP 503；包含本地offer准备的总时长约31.833秒。headersMs从requestAt起算，elapsedMs从整个probe起算，两者不能相减当作读body耗时。没有分配可见callId。
2. 运行中桌面版本26.1007.2314.0的源码表明，该请求通过Electron主进程net.fetch发送，非renderer fetch。网络异常映射499/500，HTTP响应status原样传递，所以本次503为收到的HTTP响应，不能据此确定由上游服务还是中间代理生成。
3. 原30秒CDP等待会先退出，有遮蔽该HTTP错误的风险。助手资料在本轮仍能约2.28秒读取成功。
4. 最新正式语音服务的公网路径测试：约60.8秒到达ready；服务器记录WebRTC connected、media-connected、companion-session-ready，并有助手转写和72000字节下行音频。测试没有开启麦克风，不作为真人双向语音或听感验收。
5. 测试主动挂断后23:41:36清理结束。仅保留10月8日已标记deferred的旧receipt，新测试的receipt已移除，无活动语音TCP连接。

## 本轮改动

- 创建请求显式传递40秒AbortSignal，期限到时取消原生fetch。
- CDP创建等待45秒，留出错误返回余量；资料读取等仍30秒。
- 多步骤start总预算110秒，单步失败仍及时返回；不自动重放创建请求。
- 现有手机版本已支持HTTP503提示映射，无需安装新手机包。

## 验证及边界

- Node定向36项、Python23项通过，差异空白检查通过。
- 仅重载已确认空闲且归属明确的语音Python工作进程；Electron桌面及桥接进程回读保持不变。
- 一次公网真实创建、媒体建立、停止清理成功，不能代表持续稳定。约61秒启动仍明显偏慢；前一次实际503说明该上游请求路径存在间歇不可用。
- 没有切换VPN、改阿里云、重启Codex或重新安装手机应用。
- 503不是封禁证据，也不能仅凭此区分官方内部服务故障与中间代理故障。
